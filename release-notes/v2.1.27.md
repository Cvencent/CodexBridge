# CodexBridge v2.1.27

这个版本修复 CBDP 线程投影与首页聚合计数投递。

## 修复

- **补齐 `thread.created` / `thread.updated` 事件。** Bridge 以前只发布
  message 和 turn 事件，`0x0101`–`0x0104` 从未写入事件库，导致
  `cbdp-projection.sqlite3` 的 `threads` 表长期为 0 行，设备侧线程投影同样
  拿不到数据。现在每个线程首次出现时发布 `thread.created`，标题或状态变化时
  发布 `thread.updated`，同一状态不重复发布。
- **投影可从 message/turn 事件兜底生成。** 即使某条 `0x0101`/`0x0102` 在
  升级前缺失，message 与 turn 终态事件也会补出对应 thread 行，`threads` 不再
  长期为空。
- **修复当前 `codex_state` 未投递。** 当当前计数没有匹配的历史事件时，Bridge
  会新追加一条 `0x0704`；旧代码 append 后直接返回，没有把这条事件发给刚订阅
  的会话。现在会立即投递给该会话，设备重连后能确定拿到当前计数。

## 影响

- 设备首页“运行中 / 已完成 / 失败”不再因为缺少线程投影或漏发计数而显示 0。
- `threads.list` 的投影数据与线程事件保持一致。
- CBDP 线格式、字段编号和设备侧实现均不需要改动。

## 验证

- 新增投影回归测试：仅有 message 事件时也能生成 thread 行。
- 新增投递回归测试：新追加的 `0x0704` 会立即送达订阅会话。
- 新增线程事件测试：publish 消息会生成 `thread.created`。
- 完整单元测试通过（807 项）。
