# CodexBridge v2.1.8

这个版本修复 AI Passport 设备端反馈的三项 CBDP 问题。

## 修复

- **幂等键改用 `idem`**：Bridge 之前按 `(device_id, request_id)` 查幂等表，
  而协议 §17.4 规定用 `(device_id, idem)`。`request_id` 只要求同一连接内唯一，
  设备重启后从 1 重新计数，于是新会话会与自己的 24 小时历史冲突并返回
  `IDEMPOTENCY_CONFLICT`。现在按 `idem` 查表，只有缺 `idem` 的旧客户端才退回
  `request_id`。
- **订阅回放不再阻塞设备上行**：`SUBSCRIBE` 触发的历史回放可能包含上百条
  `DELTA`，之前它在 socket 读取线程里同步发送，接收窗口排空不掉时设备
  `send()` 持续 `EAGAIN`，`AUDIO_END` 最终以 `ECONNRESET` 失败、录音被截断。
  回放现在改由每设备工作线程执行，读取循环全程继续排空设备上行。
- **`AUDIO_BEGIN` 的线程选择器校验**：`thread_ref` 现在在 `BEGIN` 时就解析，
  解析不到返回 `ERROR(NOT_FOUND, "thread_ref")`，不再静默忽略、也不会落成
  `UNSUPPORTED_FEATURE`。`AUDIO_BEGIN` / `SEND_BEGIN` 不要求先
  `thread.claim`——writer lease 与上行选线程是两件事。
- **单帧异常不再断开会话**：CBDP 会话对未预期异常返回 `ERROR(INTERNAL)` 并
  保持连接，避免设备只看到一个无原因的连接重置。

## 协议

- `PROTOCOL.md` 与 `docs/CBDP-V1-PROTOCOL.md` 写明 `SUBSCRIBE` 省略 `cursor`
  等价于 `cursor = 0`（从历史起点回放）、幂等键为 `(device_id, idem)`、
  回放必须在设备工作线程执行，以及 `AUDIO_BEGIN` 不要求 `thread.claim`。
  线格式版本仍为 `major = 1`、`minor = 0`。

## 验证

- 完整单元测试：`721` 项全部通过。
- 新增回归测试：同一 `request_id` 换新 `idem` 可再次执行、同一 `idem` 换参数
  仍冲突、订阅回放被推迟到工作线程、未知 `thread_ref` 的 `AUDIO_BEGIN` 返回
  `NOT_FOUND` 且不建立事务。
