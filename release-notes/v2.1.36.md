# CodexBridge v2.1.36

这个版本修复未批准设备也能收到 UDP 首页运行计数的问题。

## 安全问题

- **未批准设备不再收到 Codex 计数。** UDP `HOME_COUNTERS(0x1E)` 的目标注册原先
  只检查设备是否广播了 presence，完全忽略 `registration_state`。因此两台尚未
  在管理页批准、也没有配对令牌的设备，仍能收到首页“运行中”等聚合计数。
- **现在只有“已批准且持有配对令牌”的设备才被注册为目标。** pending、rejected、
  revoked 设备一律从 UDP 计数目标中移除。
- **批准与撤销会即时生效。** 在管理页批准设备后立即开始推送计数；拒绝或撤销时
  立即停止推送。

## 影响

- 未配对设备无法再通过 UDP 旁路读取主机 Codex 状态，符合统一设备协议的
  “先批准、再建立业务信道”边界。
- 已批准设备的首页计数通道行为不变。

## 验证

- pending 设备注册后不产生任何 UDP 计数帧。
- 已批准且有令牌的设备正常收到计数。
- 撤销后计数目标被移除，后续不再发送。
- 完整单元测试通过。
