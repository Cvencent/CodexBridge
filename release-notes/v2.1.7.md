# CodexBridge v2.1.7

这个版本修复手机端 1.0.6 反馈的线程状态问题：终态缺少完成时间、网络重连被
误判成失败、以及没有完成时间的线程无法记住已读。

## 修复

- **终态必须有完成时间**：`completed` / `failed` 的线程和任务现在一定带
  `completed_at > 0`。上游缺少 `completedAt` 时，Bridge 依次使用该 turn 的最后
  活动时间、线程最后更新时间、本机观测时间补齐，不再返回
  `status=completed, completed_at=0`。
- **网络重连不再落成失败**：`failed` / `interrupted` 但拿不到该 turn 自己的结束
  时间时，视为供应商重连、限流重试或流重置留下的瞬态结果，对外保持
  `working`。只有拿到结束时间，或该 turn 已静默超过陈旧窗口并以最后活动时间
  落定，才发布失败。
- **不再凭空推断完成**：缺少 turn 终态证据时不再把线程推断成 `completed`，
  无法观察的线程按 `idle` 处理。
- **终态时间戳单调**：同一线程的终态时间只增不减，后续读到旧快照不会让
  `completed_at` 回退。
- **已读不再依赖完成时间**：只要线程不处于活动状态，Bridge 就会用完成时间、
  最后更新时间或本机时间写入已读水位。历史 `completed_at = 0` 的线程在手机
  打开后也能稳定回到 `idle`，刷新不会回退。
- **四处状态一致**：`threads.list`、`thread.read`、`thread_status` 和
  `turn_completed` 现在给出同一组 `status` / `completed_at` / `turn_id`；
  瞬态失败时 `turn_completed` 返回 `status=working`、`completed_at=0`。

## 协议

- `PROTOCOL.md` 17.3 与 `docs/CBDP-V1-PROTOCOL.md` 新增的 19.7 写明终态与完成
  时间规则，供手机端和设备端对齐。线格式版本仍为 `major = 1`、`minor = 0`。

## 验证

- 完整单元测试：`718` 项全部通过。
- 新增回归测试覆盖：completed 缺时间戳自动补齐、failed 缺时间戳保持 working、
  failed 带时间戳保持终态、缺 turn 状态不推断 completed、终态时间戳单调、
  无终态时间戳时已读仍持久化、`turn_completed` 瞬态失败不落成 failed。
- 真实安装版端到端：线程列表中所有终态都带有效 `completed_at`，
  `threads.list` 与 `thread.read` 的状态和时间完全一致，标记已读后刷新仍为
  `idle`。
