# CodexBridge v1.4.5

这次更新把硬件设备第一次进入 Codex 页面的等待从十几秒压到一秒以内，修复了双实例导致的小智语音失败，并让电脑端能判断出桌面正在跑的长任务到底有没有在工作。

## 变更

- **设备主动通告（presence）**：处于 Wi-Fi 省电模式的设备只在固定监听间隔醒来，主机广播窗口一旦比这个间隔短，就可能完全收不到一个正在监听的设备的回复。设备现在可以在 TCP 监听建立后主动向 UDP `8764` 广播一次与被动应答完全相同的 JSON，桥接端常驻监听并按 `device_id + host + port` 去重。同一套协议，不做版本分支，旧固件不受影响。实测开机后进入 Codex 页：`21.1` 秒降到 `0.44` 秒。
- **拨号节奏按设备计算**：`paired_count` 与在线数量原先是全局的，只要手机保持在线，ESP32 的重拨就会被推到十几秒一次。现在拨号决策按设备独立判断，设备重启后仍然记得上次的地址与端口，发现循环先重拨已知地址、再做一次广播兜底。设备全部在线时广播放宽到 15 秒一轮，空闲功耗明显下降。
- **只允许一个实例**：两个桥接进程可以同时绑定同一组端口，而设备侧只接受一个 TCP 客户端，结果是在录音中途挤掉连接，表现为“小智没有声音”“任务出错”。现在通过命名互斥量加上管理端口探测拒绝第二个实例启动，并给出中文提示。
- **任务活跃度读自 rollout 日志**：桌面拥有自己的线程，独立的 app-server 看到的 `status.type` 一直是 `notLoaded`、`recencyAt` 停在回合开始的那一刻，长任务在设备端看起来像已经结束。手机端和硬件设备现在共用同一套活跃度判断：日志还在增长就是正在工作。`thread_settings_applied` 只是簿记不是工作，Windows 上仍在写入的日志可能报出冻结的 mtime，这两条规则都保留在实现里。
- **错误带可读文本**：电脑端每条错误同时携带机器码 `code` 与可读句子 `text`，设备只渲染 `text`，新增错误码时固件无需改动。
- **线程级实时状态**：每个设备只订阅自己正在查看的 Codex 线程，进行中状态按线程收敛，过期状态会失效，避免一台设备的轮询把全部历史推给所有设备。

## 版本

- 电脑端：`1.4.5`
- Android：`0.3.2`（本次无变化，无需重新安装 APK）

## 验证

- Python 单元测试 449 项全部通过。
- 真机 ESP32-C3：开机进入 Codex 页首次连接 `0.44` 秒完成鉴权；设备回到首页空闲后广播节奏放宽到 15 秒，机身温度较修复前下降。
- 双实例防护：第二个实例启动时被拒绝并给出中文提示，设备语音回合恢复正常。
