# CodexBridge v2.2.2

这个版本修复在电脑端 Codex 里发送消息时会出现的一次报错，报错内容为
`EPERM: operation not permitted, rename .codex-global-state.json.tmp-*`。
消息本身会发出去，但界面每次都要先弹一次错误。

## 根因

Codex 桌面端保存界面状态时会写一个临时文件，然后把它 rename 覆盖到
`~/.codex/.codex-global-state.json`。在 Windows 上，这种“覆盖式重命名”要求
目标文件的所有打开句柄都带删除共享；普通的文件读取（`open(path, "rb")`）不带，
只要有别人正在读这个文件，桌面自己的写入就会失败，于是弹出 EPERM。

CodexBridge 为了同步桌面已读状态、项目列表和会话信息，会反复读取这个文件。
它原先用的就是普通读取，因此只要撞上桌面的写入瞬间，就会让桌面报这一次错。

## 修复

- **读取桌面状态文件时带删除共享。** Bridge 现在以“读 + 写 + 删除”共享的方式
  打开该文件，桌面的覆盖式重命名不会再被正在进行的读取挡住。
- 覆盖式替换照旧可用：Bridge 自己写配置仍然是先写临时文件再原子替换。

## 影响

- 在电脑端 Codex 里发送、排队和引导不会再出现这条 EPERM 报错。
- 桌面状态同步、已读水位、项目列表和会话信息行为不变，读取结果与之前一致。

## 验证

- 独占共享读句柄期间，另一个进程对该文件的覆盖式替换可以成功。
- 对照验证：普通读取句柄仍会挡住替换（证明修复确实针对了原因）。
- 真实 `~/.codex/.codex-global-state.json` 读取正常，38 个顶层字段解析一致。
- 全量单元测试 913 项通过（新增 4 项共享读取回归测试）。
