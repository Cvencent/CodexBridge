# CodexBridge v2.1.29

这个版本修复手机新建会话返回 `desktop_handoff_pending` 的问题。

## 修复

- **共享 app-server 创建线程后立即命名。** 生产环境使用共享 app-server 时，
  `thread/start` 现在会紧接着执行 `thread/name/set`，使用中性占位名“新任务”
  提交 rollout 文件，使 Codex Desktop 可以正常 hydrate、打开和接管新线程。
- **桌面 owner 暂不可用不再丢弃线程。** 线程已经创建成功但桌面在 10 秒内没有
  完成 owner discovery 时，Companion API 不再返回 503，而是返回已创建线程并附带
  `desktop_handoff: "pending"`。首轮消息继续走共享 app-server，rollout 生成后
  桌面即可发现。
- **旧会话状态不会卡死。** handoff pending 时会移除该线程的
  `_desktop_required` 标记，避免后续 turn 永远等待不存在的桌面 owner。
- **桌面 deep link 失败也可继续使用。** 操作系统拒绝或无法打开 deep link 时，
  已创建的线程仍会返回给手机，不再变成用户看不见的僵尸线程。

## 影响

- 手机新建会话恢复正常，带不带 `model` 都不再因为桌面 handoff 超时失败。
- 正常桌面可用时仍会等待 owner discovery，保持原有的桌面接管语义。
- CBDP 设备协议和固件无需修改。

## 验证

- desktop owner 超时返回 pending 回归测试。

- pending 线程第一轮 app-server turn 回归测试。
- 完整单元测试通过。
