# CodexBridge v2.1.4

这个版本修复 CBDP 的 thread.read、message.read.update 上行与 STT 失败反馈，
并合并上一版队列暂停恢复的修复。

## 修复

- **thread.read 的 history_depth 语义**：`history_depth(0x0014)` 按协议是 `u16`，
  表示最多返回最近多少条消息。Bridge 之前把它当成泛化 `limit` 传进共享命令层，
  现在先正确解码，再映射为内部消息条数；省略时使用设备 profile 的历史预算，
  显式 `0` 表示只返回元数据。
- **message.read.update 真正落库**：该命令现在进入共享命令层，写入统一已读
  存储，手机、浏览器和其他设备会立即看到同一状态；`source` 使用真实设备身份，
  不再只回一个空成功信封。
- **紧凑引用解析**：`message_ref` / `thread_ref` 先从持久引用表解析再执行，
  解析失败返回 `NOT_FOUND`；两者同时出现但不一致时返回 `INVALID_PARAM`。
- **STT 失败可诊断**：`AUDIO_END` 识别失败时，协议错误码仍是
  `UPSTREAM_UNAVAILABLE`，但 `error_message(0x0062)` 会带上真实失败原因，
  `error_detail(0x0063)` 标记 `reason = STT_UNAVAILABLE`，设备因此能区分
  识别上游故障与音频格式错误。
- **队列暂停可恢复**：合并 v2.1.3 的修复——删除失败项、重新入队、以及 turn
  正常完成都会清除暂停，删掉失败项后重发不再卡在 pending。

## 协议

- `PROTOCOL.md` 增加“当前协议实现修正”一节。
- `docs/CBDP-V1-PROTOCOL.md` 在 17.1.1、19.5 与新增的 19.5.1 中写明上述语义，
  线格式版本仍为 `major = 1`、`minor = 0`。

## 验证

- 完整单元测试：`699` 项全部通过。
- 新增回归测试覆盖：history_depth 的类型与映射、消息已读落库、紧凑引用解析、
  STT 失败原因透传。
