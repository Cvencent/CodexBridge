# CodexBridge v2.1.12

这个版本修复首页运行计数、未读计数和设备设置更新，重点是让 CBDP 设备的首页状态与手机端统计保持一致。

## 修复

- **运行计数覆盖完整。** `codex_state.running` 现在统计 `working`、`waiting`、
  `queued`、`starting` 四种未终结状态，任务列表、CBDP task 事件和兼容网关使用同一套状态集合。
- **未读计数持久化。** 完成和失败结果写入
  `%LOCALAPPDATA%\CodexBridge\messages.json`，Bridge 重启后仍按共享
  `read-state.json` 水位恢复；同一 `message_id` 重发不会重复递增，只有已读 ACK
  或线程已读水位推进时计数才下降。
- **对外状态名称统一。** 设备消息、状态快照和嵌套任务列表把内部
  `waiting_user` 统一编码为 `waiting`，设备不再因状态字符串不匹配漏计运行任务。
- **CBDP 状态更新事件修正。** `system.codex_state(0x0704)` 与
  `0x0301` 任务事件的 `status` 编号保持非零运行态，设备可继续用计数增加触发完成提示音。
- **`thread.settings.update` 可用。** app-server 初始化声明
  `capabilities.experimentalApi=true`；`sandbox_policy` 分别适配 app-server 的
  `SandboxPolicy` 对象和桌面 IPC 的点分字符串，设备继续使用协议枚举。
- **CBDP 设置参数解码。** 补全 `0x0124` 到 `0x0128` 的正确的参数解码与枚举转换，
  二进制设备调用 `thread.settings.update` 时不再丢掉 effort、审批策略、审查者、
  sandbox 策略和 personality。

## 验证

- 完整单元测试：`734` 项全部通过。
- 新增回归测试覆盖：运行状态集合、未读计数重启恢复、同 `message_id` 去重、
  `waiting` 对外映射、CBDP 设置枚举、app-server 实验能力和桌面
  `sandbox_policy` 形状转换。
