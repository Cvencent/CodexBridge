# CodexBridge v2.1.34

这个版本解决了「CodexBridge 一运行整机鼠标就卡，关掉它立刻就好」的问题，
并明确了这属于 **PC 侧** 问题：把所有设备都关掉、没有任何设备连接时，
卡顿依然可以复现。

## 关键实测

在**零设备连接**时按进程测量 5 秒 CPU 增量（单核百分比）：

| 进程 | 说明 | CPU |
| --- | --- | --- |
| `codex app-server --listen stdio` | CodexBridge 自己多起的第二套 | **13.1%** |
| `CodexBridge.exe` | 采集轮询与 IPC | 2.2% |
| Codex 桌面自身 | 空闲 | 0.0% |

进一步隔离测量发现：这套 app-server **本身几乎不耗 CPU**——刚启动 0.0–0.3%，
被用过一次后完全空闲连续 6 个 5 秒窗口都是 **0.00%**。让它变成 5–13% 的，
是「没有任何客户端在用、却仍按最快节奏不停轮询它」。

## 修复

- **断开无响应的僵尸设备会话。** 设备上电建立连接后立刻断电时，
  `CbdpDeviceSession` 原先只在收到过数据后才把会话标记为 online，于是心跳
  分支永不进入，TCP socket 一直保持 ESTABLISHED（实测挂起 11 分钟以上）。
  “有设备在线”的判断因此永远为真，采集永远无法降频。现在握手完成即进入
  心跳，连续 3 次无 PONG 按 CBDP v1 协议断开，ping 写入失败也直接结束会话。
- **重拨不再伪造在线时间。** `_sync_one` 原先在每次重拨尝试前写入
  `last_seen`，已断电的已配对设备每 5 秒被刷新一次（实测每 20 秒精确前进
  17.5 秒）。现在只有真实会话心跳或设备主动广播才更新时间。
- **活跃线程改为增量重读。** 实测单次 `thread/turns/list` 冷读约 **134 MB**、
  `thread/list(limit=20)` 约 6.5 MB，而 `thread/read` 元数据只要 8 KB。旧代码
  对任何“看起来活跃”的线程每 5 秒无条件重读整条线程，导致磁盘被反复读。
  现在用 rollout 文件的 `mtime_ns + size` 作为变更令牌：日志没变就直接复用
  上次详情，日志一增长立即重读；同时缓存线程到 rollout 的路径解析，避免每轮
  扫描目录。
- **后台校准不再常驻桌面共用管道。** 与 Codex Desktop 共用的
  `\\.\pipe\codex-ipc` 原先由后台校准每 30 秒触发一次常驻读取；本进程读得慢时
  会回压桌面端写入。线程状态已由 app-server 列表 + rollout 日志对账得出，
  写路径仍按需探测 desktop owner，因此周期性探测改为默认关闭。
- **空闲时不再全速轮询 Codex。** 采集与伴侣校准改为按需节奏：
  - 存在在线设备会话或手机事件流订阅时，保持原来的 **5 秒**节奏与实时推送，
    行为与旧版完全一致；
  - 无人连接且未开启常开采集时，降为 **60 秒**兜底刷新，数据仍在持续采集，
    不会读到空列表；
  - 慢速休眠期间探测到客户端连上，会**立刻打断休眠并马上刷新**。
  - 实测：无人连接 `0.00%–0.31%` 单核；客户端连上后立刻恢复，10 秒内推送
    12 条记录，`2.19%` 单核。
- **长线程改为有界分页读取。** 不再用 `thread/read + includeTurns=true` 一次
  拉取整条线程（实测单行 84.7 MB，`json.loads` 持 GIL 约 2 秒），改为元数据 +
  turns 摘要页 + 最新 turn 的头尾 items 页。
- **限制每台设备的 CBDP 长连接流。** 防止设备为同一目标反复建流导致线程堆积。
- **新增「Codex 采集」开关**（管理页 → 偏好 → 启动与运行），语义是**空闲节奏**
  而非功能开关：默认关闭 = 空闲降频；开启 = 空闲也保持全速。**任何情况下都
  不会**关闭 app-server、拒绝设备或手机的按需读取、或停止消息库更新。

## 影响

- 没有设备连接、人也不在操作电脑时，CodexBridge 不再持续消耗单核 CPU，
  鼠标与系统交互不再因此卡顿。
- **功能没有减少**：设备连接、心跳、语音、任务列表、审批、队列与 CBDP 线协议
  全部照常；客户端一到就恢复全速实时推送。

## 验证

- 完整单元测试通过（856 项）。
- 本机实测（dotii 设备在线、Codex 正在输出）：CodexBridge 本体 CPU 从
  `5.83%` 降到 `0.86%` 单核；独立 app-server 从 `10.7%` 降到 `4.58%`；
  日志未变化的采集轮次读盘为 `0 KB`。
- 按需节奏实测：无人连接 `0.00%–0.31%` 单核；客户端连上后立即恢复并在 10 秒内
  推送 12 条记录。
- 端到端 HTTP 验证（后台采集默认关闭状态下）：设备能力配置、语音设置、通用设置、
  手机伴侣状态、设备列表、设备按需读取 Codex 目录、切回全速常开均正常。
