# CodexBridge v2.0.0

这是 CodexBridge 的大版本升级：Bridge 核心从以 JSON 行消息为主的实现，升级为以 CBDP v1 事件主链、SQLite 投影和统一命令模型为核心的新架构，同时保留旧设备的兼容接入路径。

## 主要变化

### CBDP v1 二进制协议

- 新增 CBDP v1 固定头、TLV、CRC、鉴权、能力位图和分片编解码。
- 新增 `HELLO / WELCOME / AUTH / AUTH_OK` 会话握手，以及 `PING / PONG` 心跳、`RESULT / ERROR`、订阅、ACK、命令和 resync 流程。
- 设备发现同时支持 CBDP 发现应答和旧 JSON 发现应答；已配对设备继续复用原有的发现、TCP 会话、能力协商和重连路径。
- 旧 JSON 行协议通过兼容网关映射到 CBDP v1 事件和命令，不建立第二套业务状态。

### 单一事件事实源

- 新增追加式事件主链，使用 SQLite WAL 保存全局序号、主题序号和 revision。
- 新增线程、消息投影和稳定引用注册表；设备读取优先使用投影，不再直接依赖桌面线程的完整快照。
- 新增订阅、cursor 恢复、待发送窗口和 writer lease；同一线程的写入由 Bridge 串行化，外部直写会触发所有权变化和重新同步。
- 保留配对、能力配置、消息、已读同步、待发送队列、语音识别、伴侣接口和托盘功能。

### 稳定性与性能

- 修复空闲时反复读取同一批未变化线程的问题。采集器现在会缓存稳定的线程详情，只在列表元数据变化、线程活跃或需要重新同步时请求完整 `thread/read`。
- 修复启动后鼠标一卡一卡的问题。根因是后台采集器周期性触发大体积线程读取，导致 Codex app-server 和 Bridge 同时出现约 1 秒的单核峰值；修复后持续 30 秒采样未再出现该周期性峰值。

## 兼容与升级

- 支持从 `1.4.10` 覆盖升级到 `2.0.0`，保留 `%LOCALAPPDATA%\CodexBridge` 下的配对设备、能力、语音、已读和录音数据。
- 旧手机和设备仍可通过兼容路径工作；新客户端应优先实现 [CBDP v1 协议](../docs/CBDP-V1-PROTOCOL.md)。
- 本次发布只包含 Windows Bridge 的安装包和便携包。手机端代码、协议适配和手机仓库迁移由独立工作流维护，不在本发布包中提供 Android APK。

## 验证

- Python 单元测试：`637` 项全部通过。
- 已在 Windows 上卸载旧版并安装 `CodexBridge-Setup-2.0.0-win64.exe`。
- 安装版管理接口、设置页、TCP/UDP 端口和单实例保护验证通过。
- 升级后保留 `5` 台设备（`2` 台硬件、`3` 台手机）、`3` 条伴侣手机记录和 `54` 个已读线程记录。
- `cbdp-events.sqlite3`、`cbdp-projection.sqlite3`、`cbdp-refs.sqlite3` 的 `PRAGMA integrity_check` 均返回 `ok`。
- 修复版安装运行后的持续采样未再出现周期性 1 秒单核峰值。
