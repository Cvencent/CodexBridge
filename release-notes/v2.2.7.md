# CodexBridge v2.2.7

这个版本修复了“设备任务确实完成了，但电脑端 Codex 侧边栏看不到”的问题。

## 现象

AI Passport 选项目后新建任务，设备端能收到回复、Bridge 也能看到完成的线程，
但 Codex 桌面端项目列表里没有这条任务。

## 根因

任务线程确实创建成功，rollout 文件和回复都正常，cwd 也是所选项目目录。
但 Codex app-server 的项目归属和 cwd 是两份独立信息：`thread/start` 必须同时
收到 `projectId`，桌面端才会把线程归入对应项目。Bridge 之前只传了 `cwd`，
因此桌面的项目归属索引里没有这条线程。

## 修复

- **创建线程时传入桌面项目 ID。** Bridge 把设备选择解析出来的项目 ID 透传到
  `thread/start` 的 `projectId`，桌面端据此持久化项目归属。
- **只传 canonical 项目 ID。** 项目名或未知 ID 不会被当成 app-server 的
  `projectId`，避免产生错误归属。
- **保留原有目录解析。** `cwd` 仍然来自项目根目录，和 `projectId` 一起下发。

## 兼容性

- 设备固件和手机端不需要改动。
- 未选择项目的旧客户端行为不变，仍按原有 cwd 或 Bridge 默认目录创建。
- 已有会话、队列、审批、附件逻辑不变。

## 验证

- 新增回归：新线程的 `thread/start` 必须携带 canonical `projectId`。
- 项目 ID、项目名和未知 ID 的解析路径分别验证。
- 全量单元测试通过。
