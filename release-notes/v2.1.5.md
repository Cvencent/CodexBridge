# CodexBridge v2.1.5

这个版本修复 Dotii 固件在 CBDP v1 联调中反馈的两项 Bridge 侧问题。

## 修复

- **`RESULT` / `ERROR` 的传输序号**：协议 §13.1 只把 `PING`、`PONG`、`ACK`、
  `CLOSE` 和发现消息豁免为 `seq = 0`，`RESULT` / `ERROR` 属于可确认帧。Bridge
  之前给它们发 `seq = 0`，导致设备无法做累计确认。现在每个响应分配非零递增
  `seq`，并在固定头 `ack_seq` 里 piggyback 已连续收到的设备序号，设备可据此
  清除重传窗口。
- **`active_state.read` / `active_state.set` 实现**：这两个方法在协议里标记为
  `[本轮实现]`，Bridge 之前落到兜底分支返回 `unsupported_method`。现在
  `active_state.read` 从 Hub 读取当前设备的活动线程与 turn，
  `active_state.set` 把设备上报的活动线程记录进 Hub；二者都要求
  `cross_device_active` 能力，引用无法解析时返回 `NOT_FOUND`。
- **能力矩阵澄清**：§28.8 明确 `active_state.read/set` 已实现，
  `events.since` 与 `resume.*` 仍为 `[本轮不实现]`，避免设备把能力声明为
  已启用却拿不到结果。

## 验证

- 完整单元测试：`702` 项全部通过。
- 新增回归测试：`RESULT`/`ERROR` 的 `seq` 非零且递增、`ack_seq` piggyback、
  `seq = 0` 的控制帧不推进确认水位、`active_state.read/set` 的读写与引用解析。
