# CodexBridge v2.2.8

这个版本修复了第二个创建路径仍然丢失桌面项目归属的问题。

## 现象

v2.2.7 后，设备新建任务仍可能出现“设备端收到回复、Codex 桌面端项目里看不到”：

- 线程 cwd 正确，例如 `F:\aiNovelWriter`
- rollout 和回复都正常
- 但桌面侧的 `projectId` 仍是空值

## 根因

设备有两种项目选择路径：

1. CBDP 的 `threads.list(project_ref)`，v2.2.7 已修复；
2. 旧的目录选择状态 `codex_project_select`，它只提供了 cwd，没有同步提供项目 ID。

第二种路径走 `CommandDispatcher` 的目录回退时只注入了 `cwd`，因此新线程仍然缺少
桌面项目归属。

## 修复

- `CommandDispatcher` 同时解析设备最近选择的 `cwd` 和项目 ID。
- 目录回退路径也会把项目 ID 传给 `start_thread`，再映射为 app-server 的
  canonical `projectId`。
- 显式传入 `cwd` 的客户端仍然只使用显式目录，不会被历史项目选择覆盖。

## 兼容性

- 设备固件和手机端不需要改动。
- 两条创建路径行为一致：目录和项目归属同时落盘。
- 未知或空项目 ID 仍会被过滤，不会写入错误的 `projectId`。

## 验证

- 新增目录回退路径的回归测试：无参数 `thread.start` 必须同时带 cwd 和项目 ID。
- 显式 cwd 不继承历史项目 ID。
- 全量单元测试通过。
