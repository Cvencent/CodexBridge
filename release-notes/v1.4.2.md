# CodexBridge v1.4.2

大线程回复不再报 IPC 帧错误、手机息屏提醒更可靠版。手机端需要同步升级到 0.3.1。

## 变更

- **修复回复长对话时报"Invalid IPC frame length"**：手机回复某条任务时，电脑端会把这条
  线程的完整状态通过桌面 IPC 推给 CodexBridge；长对话的状态帧能超过 16 MB，之前客户端把
  超出上限的帧当成损坏帧并断开连接，于是手机就报 IPC 帧错误、消息发不出去。现在正常大帧
  直接解析，超过解析预算的超大帧会被完整跳过并触发一次状态重同步，连接保持不断。实测
  17.3 MB 的状态帧可以正常接收，连续查询不再报错。
- **手机息屏后提醒更可靠**：监听服务在运行期间持有部分唤醒锁和 Wi-Fi 高性能锁，屏幕熄灭
  进入 Doze 时不再把 SSE 事件流和轮询一起挂起。
- **引导关闭电池优化**：手机端启动时如果还没允许后台运行，会弹窗说明并提供一键跳转；
  设置页新增"完成提醒"卡片，可以随时"测试提醒"（立刻弹一条完成通知并播放声音）和重新
  进入后台运行设置。
- 新增提醒卡片里的"测试提醒"走的是真实完成通知的同一套代码路径，用来判断收不到声音是
  系统设置问题还是程序问题。
- 电脑端 1.4.2，手机端 0.3.1（versionCode 17）。

## 说明

- 小米等国产 ROM 除了电池优化，还可能在"自启动管理"里限制后台；如果关闭电池优化后仍
  收不到提醒，请在系统设置里允许 CodexBridge 自启动并允许后台弹出界面。
- 手机端改动必须安装新的 0.3.1 APK 才会生效，电脑端 1.4.2 向前兼容旧手机端。

## 验证

- Python 单元测试 341 项全部通过，新增 2 项 IPC 大帧测试（超大帧跳过并保持连接、超过
  跳过上限的帧仍然判为损坏）。
- 用真实桌面 IPC 复现并回归：订阅一条大会话线程会收到 17.3 MB 的状态帧，修复前连接直接
  断开并在手机上报 Invalid IPC frame length，修复后连续 20 秒查询全部成功。
- Android 单元测试 17 项通过，`:app:assembleDebug` 构建成功。
