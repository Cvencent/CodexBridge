# CodexBridge v2.1.25

这个版本为首页新增 UDP 聚合计数通道，让设备不必常开 CBDP TCP 连接就能持续
显示"运行中 / 已完成 / 失败"。

## 新增

- **新增 CBDP 消息类型 `0x1E`（home counters）。** 复用 UDP 8764 发现端口，
  Bridge 在收到设备 presence 后，按 1~2 秒节奏向该设备单播聚合计数；
  计数变化时立即补发一次。
- **复用既有 TLV。** Payload 使用 `running_count(0x00BC)`、
  `completed_unread(0x00BD)`、`failed_unread(0x00BE)`，无需新增协议字段。
  `topic_id` 标记为 `system.thread_summaries(0x50000003)`，`qos = state`。
- **只单播、不广播。** 只有主动 presence 的设备会成为目标，避免打醒同网段
  其它设备。目标随 presence 更新。
- **TCP 路径不变。** `system.codex_state(0x0704)`、summary 订阅和命令流程
  完全保留；UDP 计数只是供首页/菜单使用的轻量旁路。设备端已有的"取较大值 +
  落地窗口"去重可避免双路径重复计数。

## 影响

- 首页播放网络电台时可以完全不建立 CBDP TCP 会话，把每条连接固定的
  `TCP_SND_BUF + TCP_WND` 预算省下来，缓解 C3 的 DMA 内存不足。
- 进入 Codex 页仍照常握手、订阅和收发任务，不受本次改动影响。

## 验证

- 新增测试：`0x1E` 帧携带三个计数、单包小于 256 字节、计数裁剪、单播目标、
  不广播、未变化不重复发送、变化立即发送、注销后停止发送、presence 注册目标。
- 完整单元测试通过（803 项）。
