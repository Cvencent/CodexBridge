# CodexBridge v2.1.2

这个版本修复 CBDP v1 联调中暴露的 DELTA 信封、错误处理和能力协商问题。
Bridge 侧修复完成后，ESP 端还需要按文末说明调整订阅方式。

## 修复

- **DELTA 缺少协议要求的信封字段**：CBDP 设备的业务事件不再走旧的 JSON
  兼容翻译层，而是统一从 Event Spine 出站。DELTA 现在携带
  `event_id`、`global_seq`、`topic_id`、`topic_seq`、`revision`，
  并按 §13.1 分配非零传输 `seq`。设备可以据此做去重、revision 顺序校验
  和 ACK/cursor 恢复。
- **DELTA 的 `topic_id` 恒为 0**：改为使用事件的真实 topic（线程 topic
  `0x1xxxxxxx` 或 system topic），不再使用兼容上下文里未赋值的默认 0。
- **DELTA 的 `seq` 恒为 0**：改用连接级 `_next_seq()`。兼容翻译器即使
  产生 DELTA 也会在 CBDP 会话上被丢弃，不会把残缺帧发上线。
- **对端 ERROR 被错误映射**：`handle_frame()` 原先没有 `TYPE_ERROR`
  分支，设备回 `INVALID_FRAME` 时会被回成 `UNSUPPORTED_FEATURE`，并触发
  设备端断线。现在收到对端 `ERROR` / `CLOSE` 会记录并保持连接，不再回错误。
- **`effective_caps` 被旧词表裁剪**：统一了旧 JSON 与 CBDP 的能力词表，
  `quota` 作为 `account`（bit 42）别名处理；`protocol = cbdp` 的设备首次
  登记默认启用设备声明的全部已实现能力，`subscribe_*`、`multi_page`、
  `device_config` 等位不再在 AUTH_OK 之前被剪掉。
- **线程对象补齐 `topic_id`**：`threads.list` / `thread.read` 的 thread
  对象现在携带稳定 `topic_id`（tag `0x0030`），面板设备据此订阅线程事件。
- **`message.updated` 的 scope 修正**：与 `message.appended/deleted` 统一
  归入 thread scope，避免订阅线程的设备漏收更新。

## 协议文档

- `docs/CBDP-V1-PROTOCOL.md`
  - §9.2 后新增“两套词表的统一（v1.0 实现修正）”

  - §21.3 补充“收到对端 ERROR 时不得回发 ERROR”

## 设备端需要配合

- 选中/打开线程后，用 thread 对象里的 `topic_id` 发送
  `SUBSCRIBE(topic_id, scope = thread (1))`；需要已读同步时再订阅
  `scope = summary (0)`。只订阅 system topic 收不到线程消息 DELTA。
- DELTA 现在都带非零 `seq`，请恢复 §13.2 校验，`seq == 0` 只用于
  PING/PONG/ACK/CLOSE/发现消息。
- 应用事件后回带 `cursor` 的 ACK，让 Bridge 推进 checkpoint。
- 收到对端 `ERROR` 时按 §21.3 分类处理，只有鉴权类错误才断开连接。
- 建议把 bit 42 的能力名从 `quota` 改为协议名 `account`（Bridge 已兼容别名）。

## 验证

- 完整单元测试：`686` 项全部通过。
- 新增回归覆盖：DELTA 信封字段与传输序号、CBDP 会话不生成兼容 DELTA、

  线程对象 `topic_id`、message 事件 scope。
