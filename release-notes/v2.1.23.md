# CodexBridge v2.1.23

这个版本修复手机伴侣接口在空闲轮询时持续占用一整个 CPU 核心的问题。

## 修复

- **鉴权不再每次请求都落盘。** `CompanionStore._reload_locked()` 过去在每个带令牌
  的请求里都会重新读取 `companion.json`，并无条件把每台手机重新投影进设备注册表；
  该投影会执行一次完整的 `devices.json` 重写（`fsync` + 原子替换）。而 `authorize()`
  和 `touch()` 每次请求各触发一次，于是手机每秒发约 `10` 个请求时，电脑端每秒要
  重写 `devices.json` 约 `20` 次。
- **按文件戳跳过重载。** 记录配对文件的修改时间与大小，未变化时直接命中内存状态，
  不再读盘解析，也不重复投影。
- **只在真正学到新手机时才投影。** 原有"过期实例不得用空列表覆盖新配对"的语义保持
  不变：重新加载时若首次看到其他实例配对的手机，仍会写进设备注册表，管理页面照常
  显示。跨实例可见性由回归测试锁定。

## 影响

- 修复前后同一条手机轮询路径实测：单次请求从 `1.96 ms` 降到 `0.011 ms`（约 `184` 倍），
  同一轮测试中的设备注册表重写次数从 `800` 次降到 `0` 次。
- 连续 `6000` 次请求的压测下，`devices.json` 与 `companion.json` 写入次数均为 `0`。
- 手机端按 `2` 秒级别轮询不会再让电脑端持续满转一个核心。

## 验证

- 新增 5 项回归测试：重复鉴权不重写注册表、重复鉴权不重读配对文件、重复拉取状态
  不重写注册表、跨实例配对仍能发布到注册表、以及既有的过期实例保护。
- 完整单元测试通过（791 项）。
