# CodexBridge v2.1.11

这个版本实现手机端交接文档中的审批链路（P0/P1），并补齐 `thread.settings`。

## 修复

- **审批提交恒 404**：Companion 的 `POST /api/companion/approvals/<request_id>`
  路由按 5 段判断，而实际路径只有 4 段，分支永远不可达。已修正，并在请求体带
  `response` 时走结构化审批、否则走 `decision`。
- **CBDP `APPROVAL_RESOLVE` 未实现**：Gateway 之前没有该消息分支，设备一提交
  就落成 `UNSUPPORTED_FEATURE`。现在按协议从消息 header 读取
  `approval_ref` / `approval_id` / `decision` / `response`；`approval_ref`
  经持久引用表解析，失败返回 `NOT_FOUND`。
- **MCP 结构化响应**：带 `response` 时转成 `approval.respond`
  （`action` / `content` / `answers` / `permissions`），不会被丢成纯
  `decision`；只带 `decision` 时仍走 `approval.resolve`。
- **审批 kind 编号修正**：按协议 §20.4 校正为 `command=0`、`file_change=1`、
  `network_access=2`、`permission=3`、`mcp_tool=4`、`user_input=5`、
  `other=6`、`mcp_elicitation=7`。旧实现把 `permissions`/`mcp`/`user_input`
  编成了错误编号。
- **审批事件推送**：`approval.requested/resolved/expired` 现在同时写入 CBDP
  Event Spine（`0x0401/0x0402/0x0403`），面板类设备能收到审批状态。
- **`thread.settings.read/update`**：新增共享命令（CBDP `0x001A/0x001B`），
  可读写 `model` / `effort` / `cwd` 以及 `approval_policy` /
  `approvals_reviewer` / `sandbox_policy` / `personality`，
  用于手机端的“请求批准 / 完全允许”切换。
- **Companion CBDP 通道共享事件总线**：修正手机通道自建空 EventSpine 的问题，
  订阅现在能收到 `system.codex_state` 等 summary 事件。
