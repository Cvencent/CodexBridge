# CodexBridge v1.4.0

手机任务与电脑端共用同一条 Codex 会话、手机模型设置真正生效版。

## 变更

- **手机新建的任务交给电脑端**：companion 之前用自己的 app-server writer 建线程，
  电脑端始终不会加载它，两边越走越远。现在手机新建任务会先通过桌面 IPC 请电脑端打开
  该任务，等到所有权真正可见后再复用这条电脑端线程；电脑端跑着的时候手机消息按 steer
  追加，而不是另起一条。
- **手机选择的模型与档位在电脑端线程上生效**：之前手机选的模型/推理档位会被静默忽略，
  回合仍按线程上一次的设置运行。现在手机在发起回合前先把选择写进线程设置，电脑端线程
  会用手机选定的模型继续。
- **手机列表状态与详情一致**：列表把电脑端持有的任务显示成空闲、聊天页却显示运行中。
  现在 rollout 日志对所有行都是权威依据：电脑端持有的线程也能落进日志判断，rollout
  存活期间 Windows 报出的冻结 mtime 不再把运行中的回合判成空闲，已结束回合的结论也不会
  在 30 分钟后过期。长日志尾部没有生命周期记录时回落到 app-server 的 turn 状态；rollout
  文件改为共享读打开，Codex 占用时也能读取。
- **不再为被占用的线程另开副本**：手机回复电脑端锁住的线程时会 fork 出一条电脑端永远不
  会打开的副本。现在先清掉磁盘上的 writer 锁，在原线程上就地继续，手机上追加的消息电脑端
  立刻能看到；只有电脑端此刻真的在跑回合时才保留 fork 回退；早期版本留下的 fork 也会被
  回收，且保留其中只在手机上产生过的回合。
- **空闲任务不再闪回运行中**：恢复或读取已完成的线程会写入一条带新时间戳的
  thread_settings_applied 记账记录并刷新 rollout mtime，手机据此误判为运行中。现在单独
  跟踪真实的活跃时间戳并排除记账事件，真正在跑的回合仍保持运行中。
- **完成通知必定有声、点击直达线程**：通知频道声音被部分厂商 ROM 覆盖时直接播放系统通知
  提示音，失败通知同样带声音与震动；点击通知按线程 id 精确打开对应任务，并重新拉起前台
  监听服务。
- **设备注册表写入在 Windows 上重试**：注册表通过临时文件加 os.replace 保存，索引器或
  杀毒软件短暂占用路径时 Windows 会以 WinError 5 拒绝替换，导致设备更新丢失。现在替换
  失败会短暂退避重试后再放弃。
- **结构化审批回复**：手机审批卡片对 input / permissions / mcp 三类审批提交 JSON 表单
  （approval.respond），不再只能回一个接受或拒绝。
- **中文日志不再让英文控制台崩溃**：Windows 控制台默认代码页（cp1252 等）无法编码中文，
  之前 print 会抛 UnicodeEncodeError 并中断启动或刷新流程，英文系统上会直接报错。现在日志
  输出在编码失败时退化为替代字符，不再影响功能。
- 电脑端版本 1.4.0，手机端 0.3.0（versionCode 16）。

## 说明

- 手机与电脑端现在操作同一条线程：电脑端打开的任务手机可以直接追加消息，无需等副本；
  电脑端此刻正在跑回合时才会回退到 fork。
- 手机重新输入上次发送失败的内容：发送失败的文本会回填到输入框，而不是直接丢掉。

## 验证

- 新增/更新 Python 单元测试 332 项全部通过（含 cp1252 控制台环境的完整回归），覆盖桌面 IPC 交接、事件流、设备命令、
  hub worker、共享 app-server、线程状态推导与注册表重试。
- Android 单元测试 17 项全部通过（ApiClient 命令封装、线程状态等）。
- 实机验证：手机新建任务后电脑端立刻可见；手机切换模型后 rollout 记录
  thread_settings_applied 并使用所选模型；通知点击精确打开线程且重启后不重复提醒。
