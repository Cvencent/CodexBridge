# CodexBridge v2.1.38

这个版本修复官方安装包缺少离线语音库的问题。此前所有 Release 里的“内置 Vosk
离线识别”实际上都无法工作，会静默回退到 Windows `System.Speech`。

## 修复

- **离线语音库现在会打进安装包。** `vosk` 通过 cffi 在运行时动态加载
  `libvosk.dll`，PyInstaller 的静态分析无法发现它。此前
  `packaging/CodexBridge.spec` 没有任何 vosk 配置，`requirements-build.txt` 也
  没有声明 vosk，因此发布产物缺失 `libvosk.dll`、`libstdc++-6.dll`、
  `libgcc_s_seh-1.dll`、`libwinpthread-1.dll` 四个原生库。
- **构建环境现在会安装 vosk。** CI 与本地构建都从 `packaging/requirements-build.txt`
  读取依赖，之前该文件不包含 vosk，导致 CI 产物连 `vosk` Python 模块都没有。
- **构建失败即拦截。** 打包脚本在生成安装包前会读取 EXE 归档，逐个校验上述四个
  原生库确实存在，缺失就报错终止，避免再次发布缺依赖的版本。

## 影响

- 已安装离线模型（`%LOCALAPPDATA%\CodexBridge\models\vosk-model-small-cn-0.22`）
  的设备，语音识别会真正走本地 Vosk，而不是回退到 `System.Speech`。
- 没有安装离线模型时，行为不变：仍然按既有回退顺序工作。
- 安装包体积会增加约 50 MB，因为包含离线识别所需的原生库。

## 验证

- 从构建产物中解出打包的 4 个原生库，实际加载
  `vosk-model-small-cn-0.22` 并完成一次识别，确认可用。
- 校验脚本双向验证：库存在时通过，人为缺失时以非零码失败并报出文件名。
- 完整单元测试通过。
