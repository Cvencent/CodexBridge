# CodexBridge v2.2.4

这个版本让设备端“选择项目 → 新建任务”真正在所选项目目录下创建任务。

## 新增

- **`thread.start` 支持 `project_ref`。** 设备从 `projects.list` 拿到的是紧凑
  项目引用，而 Codex app-server 需要真实工作目录。Bridge 现在在网关层把
  `project_ref` 解析成项目目录，再把 `cwd` 传给现有的创建逻辑，两条创建路径
  （Bridge 监听绑定与桌面交接）使用同一个目录。
- **失败语义明确。** 引用无法解析返回 `NOT_FOUND`；项目存在但没有可用目录返回
  `INVALID_PARAM`；同时提供 `project_ref` 与不一致的项目 ID 也返回
  `INVALID_PARAM`。不会静默忽略项目选择、把任务建到默认目录。

## 兼容性

- 未携带 `project_ref` 的旧客户端行为不变：仍使用请求中的 `cwd`，没有则落到
  Bridge 默认目录。
- `project_id` 只在 Bridge 内部用于查目录，不会透传给 app-server。
- 已有对话、`turn.start`、队列、审批和附件逻辑不受影响。

## 验证

- 设备选中 `one2passport` 项目后，解析结果为
  `D:\aipassport\one2passport-publish`。
- 未知项目引用返回 `NOT_FOUND`，不会创建默认目录任务。
- 按项目 ID 和项目名都能解析到同一目录。
- 全量单元测试 918 项通过（新增 4 项针对项目解析的回归测试）。
