# CodexBridge v2.1.31

这个版本修复手机连接电脑时整机出现间歇性卡顿的问题。

## 修复

- **手机接口改用 HTTP/1.1 长连接。** `companion/api.py` 之前在每个 JSON 响应里
  强制写 `Connection: close` 并置 `close_connection = True`。服务端是
  `ThreadingHTTPServer`（一条连接一个线程），于是手机的每一次轮询都会新建一条
  TCP 连接、并在电脑端新建一个线程。手机同时轮询多个端点时，实测每秒新建约
  `8`–`10` 条连接、每 `20` 秒新建约 `46` 个线程，持续不断的线程创建/销毁会挤压
  桌面输入与合成线程，表现为光标、滚动和其他交互"一阵一阵"卡住。
- **恢复 keep-alive 并加空闲超时。** 去掉强制的 `Connection: close`，让客户端
  复用同一条 socket；同时给处理线程设置 `30` 秒空闲超时，避免沉默的客户端永久
  占住一个线程。SSE（`/api/companion/events`）与 WebSocket（`/cbdp/v1/ws`）保持
  各自的流式语义不变。

## 影响

- 手机端复用一条 TCP 连接即可完成连续轮询，电脑端不再为每个请求新建线程。
- 实测同一连接连续发 `10` 个请求只使用 `1` 个 socket（修复前为 `10` 个）。
- 设备与手机保持连接时，桌面交互不再被线程风暴拖慢。

## 验证

- 新增回归测试：同一条 HTTP 连接连续发送 3 个请求，均返回 `200` 且响应头不再
  携带 `Connection: close`。
- 完整单元测试通过（817 项）。
