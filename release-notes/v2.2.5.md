# CodexBridge v2.2.5

这个版本修复设备新建的任务在电脑端 Codex 里打不开的问题。

## 现象

从 AI Passport 选项目后新建任务，电脑端 Codex 会弹出该任务，但显示：

```
Couldn't load messages
This is open in another app
Close it there to continue here.
```

## 根因

Bridge 创建线程时借用的是常驻共享 app-server。线程的写锁由创建它的 app-server
持有，而共享进程会一直活着，写锁因此永不释放。桌面 Codex 检测到该线程已被别的
进程占用，就拒绝加载，报 “This is open in another app”。

## 修复

- 创建线程改用一次性 app-server。Bridge 现在用一次性的客户端创建线程并命名，
  随后立即关闭它，写锁随之释放，桌面 Codex 可以正常接管该任务。
- 读取、订阅、turn 等其它路径继续使用共享 app-server，行为不变。

## 验证

- 实测：一次性客户端存活时写锁被持有；关闭后锁文件虽在，但已不再被持有，桌面可
  接管。
- 线程仍会在创建时命名，确保 rollout 文件落盘、桌面能看到该任务。
- 全量单元测试 920 项通过。
