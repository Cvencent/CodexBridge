# CodexBridge v2.1.20

这个版本修复多端“已完成 / 运行中 / 失败”计数不一致，以及电脑端已读不同步的问题。

## 修复

- **两台 ESP 计数不一致。** 首页聚合计数只在数值变化时写入
  `system.codex_state(0x0704)`，设备重连时 Bridge 按各自 cursor 回放有界窗口。
  旧逻辑只在窗口里完全没有计数事件时才补发当前值，于是窗口里一旦已有旧计数，
  设备就会永久停在那条历史值上。两台 ESP cursor 不同，看到的就是两个不同的旧数字。
  现在回放结束前总会补齐当前计数；若最新事件在窗口外，且 `global_seq` 不大于设备
  刚报告的 cursor（例如 `cursor = 0` 的最新窗口已越过它），Bridge 会追加一条内容
  相同的新事件再下发，保证 DELTA 的 `global_seq` 严格大于 cursor，严格客户端不会
  丢帧。
- **电脑端读取不同步到其他端。** Bridge 之前只接受 ESP 的 `read_ack` 和手机
  HTTP 的已读接口，完全没有读取桌面 Codex 的已读状态。因此在电脑上点开一个已完成
  任务后，手机和两台 ESP 仍然显示已完成、计数也不下降。现在 Bridge 会读取本机
  `~/.codex/.codex-global-state.json` 中的 `thread-user-activity-times-v1` 与
  `electron-thread-read-state-v1.unreadByIdentity`，把“桌面追踪过、且不在桌面未读
  集合中”的线程推进到同一份共享已读水位。桌面状态文件还必须晚于该线程最新终态结果，
  避免桌面尚未归类新结果时提前清掉提醒。
- 桌面已读推进后，其他在线客户端会收到 `read_state` 与空闲线程状态，
  `completed_unread` / `failed_unread` 同步减一并落回空闲。
- **未订阅事件洪泛。** CBDP 设备只订阅 summary topic 时，Bridge 不再把其它线程
  的消息事件直接推给设备。订阅后的新事件只由 gateway 按 `(topic_id, scope)` 投递；
  Hub 的广播路径不再重复发送 DELTA，attach 历史重放也必须命中订阅。会话层
  `send_event()` 再校验一次订阅，防止其它调用点绕过过滤器占用设备 lwIP 缓冲。

## 协议

- `PROTOCOL.md` 与 `docs/CBDP-V1-PROTOCOL.md` 写明桌面已读计入全局已读、summary
  订阅必须补齐当前计数，以及补发事件不得低于设备 cursor。线格式版本仍为
  `major = 1`、`minor = 0`。

## 验证

- 完整单元测试：`777` 项全部通过。
- 新增回归测试：回放窗口含旧计数时仍补发当前值、补发事件 `global_seq` 严格大于
  cursor、桌面已读推进全局水位并让其他设备收到空闲、桌面仍标记未读时不清、
  桌面状态早于结果时不误清、非本机 host 的活动记录不参与、未订阅 topic 不发送
  DELTA、已订阅事件只发送一次、Session 发送层拒绝未订阅事件。
