# CodexBridge v2.1.35

这个版本修复已完成/失败未读数量无法跟随电脑 Codex 蓝色未读点的问题。

## 修复

- **新版桌面线程没有 activity 时间也能清除未读。** Bridge 现在从
  `thread-client-id-v1:local%3A<thread_id>`、
  `thread-reference-capability:<thread_id>` 等桌面状态键判断线程已被桌面收录。
  只要桌面明确没有把该线程列在 `unreadByIdentity`，就推进共享已读水位。
- **继续保护纯手机线程。** 没有任何桌面状态记录、也没有 activity 时间的线程不会
  因为桌面文件发生无关写入而被误判已读。
- **保留时间顺序保护。** 桌面状态文件必须晚于该线程最新终态结果，Bridge 才会清除
  未读，避免桌面尚未分类结果时提前消掉提醒。

## 影响

- 电脑 Codex 没有蓝色未读点时，手机和 ESP 的已完成/失败角标会同步归零。
- 电脑仍有蓝色未读点时，Bridge 继续保留对应未读计数。
- 手机、ESP 和电脑端继续共用 `read-state.json` 的同一份已读水位。

## 验证

- 桌面认识线程但没有 activity 时间时，未读会被清除。
- 纯手机线程没有桌面记录时，未读保持不变。
- 桌面仍列出线程为 unread 时，不清除。
- 使用当前真实用户数据副本复算：`completed_unread` 从 1 降为 0。
- 完整单元测试通过。
