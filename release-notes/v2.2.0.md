# CodexBridge v2.2.0

这个版本把设备接入协议从“必须依赖 USB 或旧 JSON 配对”推进到真正的无线配对，
没有 USB 的纯 CBDP 设备也能在本机批准后自动取得令牌并上线。

## 新增

- **CBDP `PAIRING(0x1F)` 无线配对。** 设备在没有本地令牌时，在 HELLO 中携带
  `pairing_state=request`；Bridge 返回 WELCOME 后下发
  `pairing_state=offer` 和 `pairing_token`，设备保存令牌并继续使用标准
  HMAC AUTH。
- **纯 CBDP 设备可在管理页直接批准。** 设备没有旧 JSON `registration_nonce`
  时，批准动作会直接生成本机令牌并写入统一设备注册表，不再报
  `registration_nonce_missing`。
- **协议补充文档和设备端接入说明。** `docs/CBDP-V1-PROTOCOL.md` 第 11.8、
  19.16 节记录完整的配对流程与兼容规则；新增
  `docs/CBDP-0x1F-pairing-device-handoff-2026-10-24.md`，包含设备端代码位置、
  可直接照抄的实现、字节示例、安全要求和验收用例。

## 兼容性

- 已有令牌的设备不发送 `pairing_state`，HELLO/WELCOME/AUTH 流程与旧版本完全
  一致。
- 旧 JSON 硬件继续使用一次性 `registration_nonce` 和 `register_offer`。
- 手机 Companion 接口、旧协议兼容网关、订阅、命令、事件和错误码编号均未变更。

## 修复

- 底层帧编码器原先把 `0x1F` 当作保留消息类型，导致配对帧无法真正发到线上；
  现在 `0x1F` 已正式分配为 `PAIRING`。
- 纯 CBDP 设备批准失败的问题修复：批准流程不再错误地要求旧 JSON 注册 nonce。

## 验证

- 配对相关的 codec、gateway、设备管理共 95 项定向测试通过。
- 全量单元测试 906 项通过。
- 使用真实字节示例校验 `PAIRING` 帧的固定头、TLV、flags 与 request_id。
