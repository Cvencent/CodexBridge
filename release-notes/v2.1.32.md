# CodexBridge v2.1.32

这个版本修复 CodexBridge 连接设备时整机卡顿的真正根因。

## 修复

- **限制桌面 IPC 单帧的解析预算。** `DesktopIpcClient` 原来允许 `64 MB` 的
  `\.\pipe\codex-ipc` 帧，收到就整帧调用 `json.loads`。`json.loads` 是
  CPython 的 C 扫描器，解析期间**一直持有 GIL**，几 MB 的帧就会把本进程内全部
  线程（包括给手机回包的 HTTP 线程）冻住几百毫秒。而这条管道与 Codex 桌面
  共用，CodexBridge 读得慢就会反压桌面的写入，于是滚动、拖动和其他交互一起卡住。
  单帧上限现在降到 `8 MB`，更大的帧走 `resync` 路径而不是解析。
- **不再解析用不到的广播。** 读取循环原本把每个广播帧完整反序列化，但只消费
  `thread-stream-state-changed`。现在先看帧头前缀，其余广播直接跳过，
  避免为无关流量支付 GIL 代价。
- **超大广播改为请求重同步。** 超过 `2 MB` 的广播不再整帧解析，而是排入
  `resync_required`，由消费方从权威列表重新对齐。

## 影响

- Codex 桌面正在流式输出时，CodexBridge 不再因为一次大帧解析而冻结整机交互。
- 手机与设备保持连接时，桌面滚动与拖动恢复顺畅。

## 验证

- 新增广播前缀分类测试：只保留 `thread-stream-state-changed`，其余广播判定为跳过。
- 新增大广播回归测试：超过阈值的状态广播产出 `resync_required`，且 IPC 连接保持可用。
- 完整单元测试通过（819 项）。
