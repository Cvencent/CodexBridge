# CodexBridge v2.2.3

这个版本修复发送录音任务时屏幕会闪一下黑色命令行窗口的问题。

## 根因

CodexBridge 需要启动 Codex 的 app-server 子进程。查找 Codex 可执行文件时，它
用 `which("codex")` 解析，而 Windows 上这个 PATH 项指向 npm 安装的
`codex.CMD` 批处理文件。批处理文件无法直接执行，必须由 `cmd.exe` 拉起，于是
每次启动 app-server 都会创建一个控制台窗口；因为只是一闪而过，表现为屏幕闪
一下。

设备端录音发送时会触发新的 app-server 会话，所以这个现象最容易被看到。

## 修复

- **优先使用原生可执行文件。** 查找顺序改为先找 `codex.exe`，再找 Windows
  安装目录中的官方 CLI，最后才回退到 PATH 上的通用 `codex` 项。原生
  `codex.exe` 是单进程启动，不会创建任何控制台窗口。
- 显式配置的 Codex 命令优先级不变：用户或环境变量指定的路径仍然最优先。

## 影响

- 从 AI Passport 发送录音任务时不再闪烁命令行窗口。
- app-server 的启动方式、协议和会话行为不变，只是不再经过 `cmd.exe`。

## 验证

- 原生 `codex.exe` 启动后为单进程，不会派生 `cmd.exe`。
- 命令解析结果从 `codex.CMD` 变为官方 `codex.exe`。
- 显式命令优先级与自动发现行为的回归测试通过。
- 全量单元测试 914 项通过。
