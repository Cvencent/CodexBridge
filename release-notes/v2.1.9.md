# CodexBridge v2.1.9

这个版本修复 CBDP 设备收不到首页聚合计数的问题。

## 修复

- **新增 `system.codex_state` 事件**：Bridge 之前把首页计数作为 legacy
  `{"type":"codex_state",...}` 字典下发，而 `CbdpDeviceSession.send()` 只能发送
  能翻译成 CBDP DELTA 的消息，这条字典被静默丢弃，所以 CBDP 设备永远收不到
  运行计数。现在改为在 Event Spine 上追加 `system.codex_state(0x0704)` 事件，
  走 `system.thread_summaries(0x50000003)` 的 `summary` scope、`state` QoS。
- **计数字段**：事件携带 `running_count(0x00BC)`、
  `completed_unread_count(0x00BD)`、`failed_unread_count(0x00BE)`。
- **变化才发布**：运行集合或全局未读数变化时才追加事件，计数不变不重复发，
  避免日志膨胀和无意义的 radio 流量。
- **重连即刷新**：设备 attach、或主动发 `codex_state_request` 时，Bridge 直接
  补发一条当前计数的等价事件，设备不需要等下一次状态变化。
- **legacy 路径保持**：旧的 JSON 设备继续收到原来的 `codex_state` 字典，行为不变。

## 协议

- `PROTOCOL.md` 与 `docs/CBDP-V1-PROTOCOL.md` 记录事件编号、topic、scope、QoS
  和字段语义。线格式版本仍为 `major = 1`、`minor = 0`。

## 验证

- 完整单元测试：`725` 项全部通过。
- 新增回归测试：`system.codex_state` 落在 summary topic/scope、携带三个计数
  字段、计数不变不重复发布、summary 订阅者能收到对应 DELTA。
