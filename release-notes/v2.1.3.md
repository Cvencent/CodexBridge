# CodexBridge v2.1.3

这个版本修复队列暂停状态无法自动恢复的问题。用户删掉失败项或直接重发后，
队列会真正重新派发，不再需要靠编辑同一条失败记录来解锁。

## 修复

- **删除失败项后不再卡住**：`queue.delete` 删除一条 `failed` 队列项时会清除
  该线程的暂停状态；删除后线程已无失败项时同样清除。
- **重发即恢复**：`queue.enqueue` 会清除该线程的暂停并唤醒派发，用户删掉失败
  项后直接再发一条消息即可继续，不需要额外动作。
- **turn 完成后自愈**：线程有 turn 正常结束时清除遗留的陈旧暂停，避免线程
  已经恢复可用但队列仍不派发。
- **保留必要的保护**：只要该线程仍有其他 `failed` 项，删除无关的 pending 项
  不会解除暂停，仍然避免对同一错误做无上限热重试。

## 协议

- `PROTOCOL.md` 与 `docs/CBDP-V1-PROTOCOL.md` 明确：暂停状态通过
  `queue_snapshot` / `queue.list` 的 `paused` 字段暴露，且 `queue.enqueue`、
  `queue.edit`、删除失败项、以及 turn 正常完成都会清除暂停。不新增
  `queue.resume` 命令，重发本身就是恢复动作。

## 验证

- 完整单元测试：`690` 项全部通过。
- 新增队列回归测试：删除失败项后重发可派发、暂停线程上 enqueue 立即恢复、
  turn 完成清除陈旧暂停、仍有失败项时删除 pending 项保持暂停。
