# CodexBridge v1.3.15

手机副本会话可辨认、失败原因可读与列表不再闪烁版。

## 变更

- **列表刷新不再闪烁**：自动刷新间隔仍是 2 秒，但同步状态改成一行固定高度的文本
  （`已同步 · 刚刚 / N 秒前`），加载指示器只占据固定大小的槽位，不再每次轮询就把
  图标、转圈和“已同步”整行挂载/卸载。手机列表不会再一闪一闪。
- **失败原因直接显示在手机上**：`turn_completed` 事件与线程详情新增 `error_message`，
  电脑端把嵌套的 provider 错误 JSON（例如
  `{"error":{"message":"[workbuddy] upstream client (http 400): {...}"}}`）展开成一句可读
  文字。手机会话页在上一轮失败时常驻红色提示，例如
  `上一轮失败：[workbuddy] upstream client (http 400): invalid function call parameters`，
  不用再去电脑端翻日志。失败通知也已带声音与震动。
- **副本会话在电脑端可辨认**：电脑端占用线程时手机回复仍写入同历史的 fork，但 fork 现在
  会被重命名为 `手机继续 · <原任务名>`（`thread/name/set`），电脑端刷新任务列表后就能看出
  哪条是手机继续的会话，不再和原任务长得一模一样。重命名不会改掉手机端显示的任务名。
- **新增 `thread_forked` 事件**：fork 建立时立即广播 `thread_id`、`continued_as` 与 `title`，
  手机据此立刻在会话页提示“手机回复写入副本会话”，不必等下一次轮询。
- **`GET /api/companion/threads/<id>` 返回 `continued_as`**：手机打开旧会话时即可知道当前
  回复会落在哪个副本里。
- 电脑端版本 1.3.15，手机端 0.2.9（versionCode 11）。

## 说明

- 电脑端 Codex 打开某个任务时会长期持有该线程的 writer 锁，这是 app-server 的单 writer
  约束，CodexBridge 无法抢占。因此“手机在电脑端正在使用的任务里回复”只能在副本会话中
  继续；副本包含完整历史，但电脑端不会实时看到手机的新消息，需要刷新任务列表后在
  `手机继续 · …` 那条任务里查看。
- 手机回复报 `invalid function call parameters` 属于自定义模型提供方（workbuddy /
  Auto/DeepSeek-V4.1-Flash）侧的工具调用参数不兼容，不是 CodexBridge 的网络问题；现在
  该原因会原样显示在手机上。

- 新增 `thread_snapshot` / 线程详情输出 `error_message` 的单元测试。
