# 手机端联调问题交接

日期：2026-10-18

范围：手机客户端或其 Android 模拟器在连接 CodexBridge Companion API 时需要修正的问题。

说明：本文只记录排查结果，未修改仓库中的手机端代码。

## 观察到的现象

1. Android 模拟器组件 `netsimd.exe` 持续向本机 `127.0.0.1:8568` 发起连接。
2. 在一次 2 分钟观察中，Bridge 看到同一个模拟器建立了 35 条 `ESTABLISHED` 连接。
3. 新连接大约每 5 到 7 秒出现一次，即使管理页面显示手机设备处于离线状态，也没有停止。
4. 频繁连接会触发 Companion 服务后台刷新，并进一步请求 Codex 线程数据；严重时会拉起额外的 Codex app-server 工作。

## 请手机端修正

### 1. 不要为每次轮询新建一条长期占用的连接

- 实时状态和事件优先使用 `/api/companion/events` SSE，保持一条事件连接。
- 普通 HTTP 请求应复用连接，或在收到 `Connection: close` 后干净关闭，再按计划重连。
- 不要在短时间内并发建立多条状态、线程和详情请求。

### 2. 后台时停止高频轮询

- 应用进入后台、锁屏或页面不可见时，应暂停状态轮询，或把周期放宽到至少 30 秒。
- 回到前台后先做一次同步，再恢复实时事件连接。
- 已经建立的旧轮询任务必须取消，不能继续堆积。

### 3. 失败重试必须退避

- Bridge 离线、HTTP 超时或返回 401/403 时，不要固定每几秒重试。
- 使用指数退避并加入随机抖动，例如 2、4、8、16、30 秒，最大 60 秒。
- 收到 `Connection: close` 是正常协议行为，不是错误，不应立即无限重连。

### 4. 离线状态不能继续触发业务查询

- 设备记录显示离线或连接失败后，应停止线程列表、线程详情和 Codex 状态高频刷新。
- 恢复连接时，使用一个状态请求和 SSE 事件恢复界面，不要重新并发拉取全部数据。

## 手机端验收标准

- Bridge 管理页保持手机离线 10 分钟，手机端不应持续新建到 `8568` 的连接。
- Bridge 正常在线时，手机前台只保持一条 SSE 事件流和必要的低频普通请求。
- 在 Bridge 停止、恢复、Wi-Fi 切换三种场景下，手机端使用退避重连且不会积累并发线程。
- `Connection: close` 响应出现后，手机端能够正常关闭连接并继续工作。

## Bridge 侧已处理

- 硬件采集和手机 Companion 现在共享同一套 Codex app-server，不再因为手机请求创建第二套引擎。
- Codex app-server 以低于正常优先级运行，降低后台批量解析对前台交互的影响。
- Companion API 的普通 JSON 响应会返回 `Connection: close` 并主动结束连接，避免服务端线程长期堆积。
